# Скобки и разыменование

```c
int a[] = {10, 20, 30};
int *p = a;
```

Чему равны `*p + 1` и `*(p + 1)`? Где мы прибавляем единицу к *числу*, а где — к *указателю*?

<!-- *p + 1 группируется как (*p) + 1 и даёт 11. *(p + 1) — это p[1], то есть 20. -->

# Разминка: четыре правые части

```c
int a[] = {10, 20, 30, 40};
int *p = a + 1;
```

1. `p[-1]`
2. `p + 3`
3. `*(p + 3)`
4. `p + 4`

Что можно вычислить? Что получится?

# Граница массива — тоже позиция

| Индекс от начала `a` | Элемент | Адрес |
| --- | --- | --- |
| `0` | `a[0]` → `10` | `a` |
| `1` | `a[1]` → `20` | `a + 1`, то есть `p` |
| `2` | `a[2]` → `30` | `a + 2` |
| `3` | `a[3]` → `40` | `a + 3` |
| `4` | *Нет элемента* | `a + 4` — сразу за концом |

`p[-1]` → `10`. `p + 3` → `a + 4`: это указатель за концом (*one-past*), поэтому `*(p + 3)` — UB. Вычисление `p + 4` — тоже UB, уже на этапе сложения.

<!-- Вопрос 1: отрицательный индекс сам по себе не является ошибкой. Вопрос 4: даже если не обращаемся к памяти, вычисление уже вышло за допустимый диапазон. -->

# Разность и сравнение указателей

```c
int a[4] = {10, 20, 30, 40};
int *p = a + 1, *end = a + 4;
ptrdiff_t distance = end - p;  // 3
int b[4];
int *q = b;
```

- Вычитание внутри одного массива даёт разность в *элементах*. `end` допустим, результат должен помещаться в `ptrdiff_t`.
- `p == q` проверяет *равенство указателей*, не читая элементы. Для этих двух `int *` сравнение допустимо и даёт `0`; `p != q` даёт `1`.
- `p < q` и `q - p` здесь — *UB*: указатели относятся к разным несвязанным массивам.

<!-- ptrdiff_t объявлен в <stddef.h>; формат printf — %td. Сравнение указателей совместимых типов на равенство допускается без требования общего массива. Для == также есть правила для нулевых указателей и void *. Для сравнений на порядок у членов агрегатов есть отдельные правила; здесь рассматриваются независимые массивы. -->

# Проход по полуинтервалу

```c
int a[] = {10, 20, 30, 40};
const int *end = a + sizeof a / sizeof a[0];

for (const int *p = a; p != end; ++p) {
    printf("%d\n", *p);
}
```

- Диапазон *`[a, end)`* включает первый элемент, но не `end`.
- Проверка идёт *до разыменования*. Последний `++p` доходит до `end`, и тело больше не выполняется.

# Читаем элемент после проверки

В исходном цикле после тела при `i == 3` вычисляется `a[++i]`. Это *чтение `a[4]`* до следующей проверки `i < 4`.

```c
int a[] = {10, 20, 30, 40};

for (size_t i = 0; i < sizeof a / sizeof a[0]; ++i) {
    printf("%d\n", a[i]);
}
```

Выход за границы — *неопределённое поведение*. Результат запуска не доказывает, что обращение корректно.

# Адрес не продлевает жизнь объекта

```c
int *p;
{
    int x = 42;
    p = &x;
    printf("%d\n", *p);   // корректно
}
// printf("%d\n", *p);   // UB: x больше не существует
```

- Область видимости отвечает на вопрос «где доступно *имя*?».
- Время жизни отвечает на вопрос «когда существует *объект*?».
- Имя `p` всё ещё видно, но сохранённый адрес нельзя использовать.

# Пусть объект принадлежит вызывающему

Если нужен просто результат, верните *значение* `int`. Если нужно записать его в чужой объект, передайте адрес этого объекта:

```c
void set_answer(int *out) {
    *out = 42;
}
```

```c
int value;
set_answer(&value);
printf("%d\n", value);  // 42
```

В этом вызове объект `value` жив и во время записи, и при чтении после возврата.

# Блочная видимость, статическое время жизни

```c
int *counter(void) {
    static int value = 0;
    return &value;
}
```

- Имя `value` видно только внутри функции.
- Сам объект существует *всё время выполнения программы*.
- Каждый вызов возвращает адрес *того же объекта*, а не нового счётчика.

# Массив не является указателем

```c
int a[4] = {10, 20, 30, 40};
int *p = a;
```

- Объект `a` имеет тип `int[4]` и хранит четыре `int`.
- В инициализаторе `p` выражение `a` преобразуется в `&a[0]` типа `int *`.
- Это *array-to-pointer decay*: возникает значение указателя. Массив не копируется и не меняет свой тип.

---

# Когда преобразования нет

| Контекст в C99 | Пример | Что используется |
| --- | --- | --- |
| Операнд `sizeof` | `sizeof a` | Размер всего массива |
| Операнд унарного `&` | `&a` | Адрес всего массива |
| Строковый литерал инициализирует массив | `char s[] = "ab";` | Элементы `'a'`, `'b'`, `'\0'` |

Третье исключение относится именно к *строковому литералу* в инициализаторе массива. В `const char *s = "ab";` он преобразуется в указатель.

<!-- Полная формулировка C99 §6.3.2.1 п. 3. Опционально: если массив объявлен register, его преобразование даёт неопределённое поведение. -->

# Как читать объявления типов

| Объявление | Порядок чтения | Тип объекта |
| --- | --- | --- |
| `int *a[3];` | `a` → `[3]` → `*` → `int` | Массив из трёх указателей на `int` |
| `int (*p)[3];` | `p` → `*` → `[3]` → `int` | Указатель на массив из трёх `int` |
| `int m[2][3];` | `m` → `[2]` → `[3]` → `int` | Массив из двух массивов по три `int` |

*Вправо → влево → вверх.* От имени сначала читаем справа `[]` или список параметров, затем слева `*`. Не перескакиваем через скобки: выходим из них на уровень выше и повторяем. Базовый тип читаем последним.

Для `int (*)[3]` мысленно вставьте имя: `int (*p)[3]`.

---

# Как читать объявления функций

```c
int *get(size_t i);
int (*op)(int, int);
int (*ops[3])(int, int);
```

- `get`: параметры → `*` → `int`. Это *функция*, возвращающая `int *`.
- `op`: `*` → параметры → `int`. Это *указатель на функцию*, возвращающую `int`.
- `ops`: `[3]` → `*` → параметры → `int`. Это массив из трёх таких указателей.

Без имени: `int (int, int)` — тип функции, `int (*)(int, int)` — тип *указателя* на неё.

# `sizeof a` и `&a`: что меняется?

```c
int a[4] = {0};
int *p = a;            // на первый int
int (*whole)[4] = &a;  // на весь массив
```

- `sizeof a` → `4 * sizeof(int)`; `sizeof p` → `sizeof(int *)`.
- `p + 1` указывает на `a[1]`.
- `whole + 1` указывает *сразу за всем массивом*. Шаг измеряется одним `int[4]`, а не одним `int`.

На схеме с начальным адресом `0x1000` и `sizeof(int) == 4` получим соответственно `0x1004` и `0x1010`.

<!-- Не подменять типы совпадением начальных адресов. Для арифметики whole указывает на отдельный объект, рассматриваемый как массив длины 1. -->

# Запись `[]` в параметрах функции

```c
void clear(size_t n, int a[4]);
// Или: void clear(size_t n, int *a);
```

- В *объявлении параметра* `int a[4]` корректируется до `int *`. Число `4` не входит в тип функции и не создаёт проверку при вызове.
- При вызове `clear(n, data)` выражение `data` преобразуется в указатель на первый элемент. Функция получает адрес, а не копию массива.
- Длину `n` передаём отдельно. Вызывающий обязан передать доступный диапазон.

<!-- Два разных правила: корректировка типа параметра (§6.7.5.3) и преобразование выражения-аргумента (§6.3.2.1). Это два варианта записи; в одной программе лучше использовать один вариант последовательно. Компилятор может учитывать [4] для предупреждений. [static 4] задаёт дополнительное требование к аргументу; это тоже не автоматическая проверка при вызове. -->

---

# Длину считаем там, где есть массив

```c
void clear(size_t n, int *a) {
    for (size_t i = 0; i < n; ++i) {
        a[i] = 0;
    }
}
```

```c
int data[] = {5, 7, 9};
clear(sizeof data / sizeof data[0], data);
```

Внутри `clear` у `sizeof a` другой смысл: *размер указателя*. Деление `sizeof a / sizeof a[0]` не восстанавливает длину.

---

# Два способа хранить матрицу

```c
int m[2][3] = {{1, 2, 3}, {4, 5, 6}};
int flat[2 * 3] = {1, 2, 3, 4, 5, 6};
```

1. *Двумерный массив* `m`: элементы внешнего массива — строки. Для элемента используем `m[i][j]`.
2. *Одномерный массив* `flat`: все `int` лежат в одном массиве. Индекс вычисляем сами: `flat[i * cols + j]`, где `cols = 3`.

Например, `m[1][2]` и `flat[1 * 3 + 2]` оба дают `6`. Данные идут в одном порядке, но типы массивов разные.

---

# Вариант 1: массив строк

```c
int m[2][3] = {{1, 2, 3}, {4, 5, 6}};
```

```text
Память:   [ 1 ][ 2 ][ 3 ]  [ 4 ][ 5 ][ 6 ]
           └── m[0] ───┘    └── m[1] ───┘
```

- Тип `m`: массив из двух элементов типа `int[3]`.
- Строки лежат *подряд*. Быстрее меняется последний индекс.
- При `sizeof(int) == 4`: `sizeof m[0][0]` → `4`, `sizeof m[0]` → `12`, `sizeof m` → `24` байта.

---

# Инициализация двумерного массива

```c
int a[][3] = {{1, 2}, {4}};  // две строки
int zeros[2][3] = {0};       // шесть нулей
// int bad[][] = {{1}};      // неизвестен тип строки
```

- У массива постоянного размера с инициализатором можно пропустить *число строк*. Ширину строки нужно указать.
- Недостающие элементы `a` обнуляются: строки `{1, 2, 0}` и `{4, 0, 0}`.

---

# Две индексации — два шага

| Выражение | Тип | Результат |
| --- | --- | --- |
| `m` | `int[2][3]` | Всю матрицу |
| `m + 1` | `int (*)[3]` | Адрес `m[1]` |
| `m[1]` | `int[3]` | Вторая строка |
| `m[1] + 2` | `int *` | Адрес `m[1][2]` |
| `m[1][2]` | `int` | Элемент `6` |

`m[i][j]` — это `*(*(m + i) + j)`: *строка → элемент*.

<!-- Сравнить m + 1 (тип int (*)[3], шаг 3 * sizeof(int)) и m[0] + 1 (тип int *, шаг sizeof(int)). -->

# Непрерывность не отменяет границы строки

```c
int m[2][3] = {{1, 2, 3}, {4, 5, 6}};
int *first = &m[0][0];
```

- `first + 3` — позиция сразу за строкой `m[0]`.
- `first[3]` и `m[0][3]` — *UB*, хотя следующая строка лежит сразу за первой.
- `m[1][0]` — корректный способ прочитать `4`.

Если нужен один индекс для всех элементов, объявите отдельный *одномерный массив*.

<!-- C99, приложение J.2: индекс за пределом строки остаётся ошибкой, даже если вычисленный адрес выглядит доступным. Не использовать &m[0][0] как int* для обхода всей матрицы. -->

# Вариант 2: одномерный массив

```c
enum { ROWS = 2, COLS = 3 };
int flat[ROWS * COLS] = {1, 2, 3, 4, 5, 6};

for (size_t i = 0; i < ROWS; ++i) {
    for (size_t j = 0; j < COLS; ++j)
        printf(" %d", flat[i * COLS + j]);
    putchar('\n');
}
```

- Перед строкой `i` лежат `i * COLS` элементов. Прибавляем столбец `j` и получаем *линейный индекс*.
- Здесь `flat[3]` — первый элемент второй строки. Массив `flat` действительно содержит шесть `int`.

<!-- Для просмотра по строкам внешний цикл перебирает i, внутренний — j. Если размеры получены во время работы, нужно проверять их и произведение до выделения буфера. -->

# Массив указателей на переменные

```c
int x = 1, y = 2, z = 3;
int *refs[3] = {&x, &y, &z};

for (size_t i = 0; i < 3; ++i)
    *refs[i] += 10;
```

- `refs[i]` хранит адрес. Запись `*refs[i]` читается как `*(refs[i])`.
- Что стало с `x`, `y` и `z`? Объекты, на которые указывают элементы `refs`, не обязаны лежать рядом.

<!-- Результат: x = 11, y = 12, z = 13. Сам массив refs содержит адреса, а не копии значений. -->

# Отдельный случай: строки разной длины

```c
int x[] = {10, 20, 30};
int y[] = {40, 50};
int *rows[] = {x, y};
```

- `rows[1][1]` → `50`. Первые `[]` читают *указатель* из массива, вторые — элемент по этому указателю.
- Длины строк различаются: `rows[1][2]` — выход за границу `y`.
- `rows` преобразуется в `int **`. У непрерывной матрицы `m` результат другого типа: `int (*)[3]`.

Это *массив адресов*, не один непрерывный массив `int`. Длину каждой строки здесь нужно хранить отдельно.

---

# Матрица как параметр: известная ширина

```c
void first_column_zero(size_t rows, int m[][3]) {
    for (size_t i = 0; i < rows; ++i) {
        m[i][0] = 0;
    }
}
```

- Фактический тип параметра — `int (*m)[3]`.
- Число строк передаём отдельно. Ширина `3` сохраняется в *типе строки* и задаёт шаг `m + 1`.
- Записи `int m[][]` и `int **m` не заменяют `int m[][3]`: в первой нет ширины строки, во второй ожидается указатель на `int *`.

---

# VLA: длина известна при выполнении

```c
int n = 3;
int a[n];  // variable length array, VLA

n = 5;
printf("%zu\n", sizeof a / sizeof a[0]);  // 3
```

- Длина вычисляется, когда выполняется объявление `a`. На тот момент `n == 3`.
- Размер *этого экземпляра* не меняется. Новое значение `n` не расширяет `a`.
- `sizeof` для VLA может вычисляться во время выполнения.

<!-- Нетривиальное замечание: const int n = 3 не становится целочисленным константным выражением в C99. enum { N = 3 }; int b[N]; — массив фиксированной длины. -->

---

# VLA: ограничения C99

- Вычисленная длина должна быть *положительной*. Если она зависит от ввода, проверьте и нижний, и разумный верхний предел **до объявления**.
- Локальный объект VLA живёт *от объявления до выхода из его области видимости*. Нельзя объявить объект VLA на уровне файла или с `static`.
- Для VLA нельзя написать `int a[n] = {0};`. Заполняйте элементы в цикле.
- VLA подходит для небольших ограниченных размеров; большие массивы требуют другого способа выделения памяти.

# Матрица как параметр: ширина из аргумента

```c
void clear_matrix(size_t rows, size_t cols,
                  int (*m)[cols]) {
    for (size_t i = 0; i < rows; ++i)
        for (size_t j = 0; j < cols; ++j)
            m[i][j] = 0;
}
```

- `m` — указатель на строку переменной длины. В параметре запись `int m[][cols]` даёт тот же тип.
- Перед вызовом: `cols > 0`, ширина совпадает с реальной шириной строки, доступно `rows` строк.

<!-- cols должен быть объявлен раньше m. rows — число строк для обхода, оно не зашито в тип указателя. Пример вызова: int m[2][3] = {{1, 2, 3}, {4, 5, 6}}; clear_matrix(2, 3, m); -->

# Проверьте себя: тип, граница или время жизни?

```c
int m[2][3] = {{1, 2, 3}, {4, 5, 6}};
```

1. Какой тип у `m + 1`? А у `&m + 1`?
2. Что даёт `sizeof m / sizeof m[0]`?
3. Допустимо ли `m[0][3]`?
4. Внутри блока объявили `int temp[n]`, где `n > 0`, и сохранили `temp` в `int *p` снаружи. Можно ли прочитать `*p` после выхода из блока?

---

# Самопроверка: разбор

1. `m + 1` — `int (*)[3]`, адрес второй строки. `&m + 1` — `int (*)[2][3]`, позиция *за всей матрицей*.
2. `sizeof m / sizeof m[0]` → `2`: размер матрицы делим на размер строки.
3. `m[0][3]` — UB: индекс `3` не входит в первую строку.
4. Читать `*p` нельзя: время жизни `temp` закончилось при выходе из блока.

# Практика: сколько раз встречается число?

```c
size_t count_matches(size_t rows, size_t cols,
                     int (*m)[cols], int key);
```

Напишите функцию: она считает вхождения `key` в матрице и не меняет элементы. Ширина `cols` положительна и совпадает с реальной, доступны `rows` строк.

```text
Матрица 3×4:   4  1  4  0
               2  4  3  4
               7  8  9  1
```

Ожидаемые ответы: для `4` → `4`, для `99` → `0`.

# Решение: обходим строки и столбцы

```c
size_t count_matches(size_t rows, size_t cols,
                     int (*m)[cols], int key) {
    size_t count = 0;
    for (size_t i = 0; i < rows; ++i) {
        for (size_t j = 0; j < cols; ++j) {
            if (m[i][j] == key) {
                ++count;
            }
        }
    }
    return count;
}
```

<!-- size_t объявлен в <stddef.h>. Матрица теста: int m[3][4] = {{4,1,4,0}, {2,4,3,4}, {7,8,9,1}};. Вызовы count_matches(3, 4, m, 4) и count_matches(3, 4, m, 99). Время O(rows * cols), дополнительная память O(1). В строгом C99 int (*)[cols] не преобразуется неявно к указателю на массив const int; неизменность здесь задана в условии и видна из тела функции. -->

# Три вопроса перед `p[i]`

1. *Объект жив?* Указатель не пережил объект, к которому обращаемся?
2. *Тип верен?* Шаг — один элемент нужного типа: `int`, `int *` или целая строка?
3. *Индекс в границах?* Считаем внутри нужного массива, а указатель за его концом не разыменовываем.

Для передачи массива отдельно передаём его длину; для матрицы согласуем и ширину строки.
