# Лайвкодинг: указатели и массивы

[Слайды с условиями](../slides/pointer-arrays-practice.md) · [Заготовка, GoogleTest и сборка](../livecoding/README.md).

### 1. Указатели и массивы: практика

Сначала договариваемся о размерах и о том, куда пишем результат. На занятии редактируем `starter.c` и запускаем набор, соответствующий выбранной задаче. Готовые реализации для преподавателя — в `solutions.c`.

### 2. Задача 1: минимум и максимум

1. Если `n == 0`, вернуть `0` без чтения массива и записи в выходные параметры.
2. Иначе положить `min = max = a[0]`, затем для каждого `a[i]` с `i = 1` обновить обе границы. Спросить, почему нельзя начать с нуля: на полностью положительном массиве минимум получился бы ложным, на отрицательном — максимум.
3. Записать `*lo = min`, `*hi = max` и вернуть `1`. Один проход, `O(n)` времени и `O(1)` дополнительной памяти. GoogleTest: `MinMax`.

### 3. Задача 2: транспонировать прямоугольник

1. Подготовить результат размером `cols × rows`. Прочитать типы параметров: `int (*)[cols]` и `int (*)[rows]`; размер второй оси задаёт шаг строки.
2. Во внешнем цикле перебрать `i < rows`, во внутреннем — `j < cols`. Для каждой ячейки выполнить `dst[j][i] = src[i][j]`. Проследить переход `(1, 2) → (2, 1)` и проверить обе границы по рисунку.
3. Исходник и результат лежат в разных буферах: запись не уничтожит ещё не прочитанное значение. Время `O(rows * cols)`. GoogleTest: `Transpose`.

### 4. Задача 3: квадрат на месте

Если обойти все пары, каждый обмен произойдёт дважды. Для каждой строки `i` перебираем только `j = i + 1 … n - 1`; через временную переменную меняем `a[i][j]` и `a[j][i]`. Каждая зеркальная пара обрабатывается один раз, диагональ — ни разу. Это `n * (n - 1) / 2` обменов и `O(1)` дополнительной памяти. GoogleTest: `TransposeSquare`.

### 5. Задача 4: перемножить матрицы

1. Внешние циклы перебирают строки результата `i < m` и столбцы `j < n`.
2. Для каждой ячейки завести `long long sum = 0` и по общей оси `t < k` прибавлять `(long long)a[i][t] * b[t][j]`. Приведение делаем до `*`: результат умножения может не поместиться в `int`.
3. После внутреннего цикла один раз записать `c[i][j] = sum`. Старое значение результата не нужно, входы не меняем. Время `O(m * k * n)`. GoogleTest: `Direct`.

### 6. Эксперимент: транспонировать `B`

Повторно используем `transpose(k, n, b, bt)`: у `bt` размеры `n × k`. В `matmul_bt` заменяем `b[t][j]` на `bt[j][t]`. В цикле по `t` читаем две последовательности соседних элементов вместо чтения `B` с шагом `n`. Транспонирование только `A` при таком же порядке циклов не помогает: её строка уже шла подряд, а столбец `B` остаётся с большим шагом. Другой способ улучшить локальность без копии — порядок `i–t–j` с предварительным обнулением результата.

Запустить в Release цель `matmul_demo`: она замеряет `512`, `1000` и `1024`. Сравнить время с уже готовой `Bᵀ` и полный путь с её построением. У замера есть проверка совпадения результатов, а у варианта с `Bᵀ` — набор GoogleTest `Transposed`. Ускорение зависит от кэша, шага, компилятора и размера задачи; по одному замеру времени нельзя отделить эффект кэша от векторизации. Для небольших матриц подготовка может не окупиться.

### 7. Первая позиция для вставки

Идея: всё левее `lo` строго меньше `key`, всё начиная с `hi` — не меньше `key`. Ещё не проверенные элементы лежат в `[lo, hi)`. Ответ может быть равен `hi`, в том числе `n`.

1. Начать с `lo = 0`, `hi = n`. Пока `lo < hi`, вычислить `mid = lo + (hi - lo) / 2`.
2. Если `a[mid] < key`, самый левый допустимый индекс уже правее `mid`: присвоить `lo = mid + 1`. Иначе присвоить `hi = mid`: позиция `mid` всё ещё может быть ответом, но сама ячейка уже проверена. В полуинтервале правая граница не включается, поэтому `mid - 1` не нужен. При `mid == 0` вычитание из беззнакового `size_t` дало бы большое число вместо `-1`.
3. При `lo == hi` вернуть `lo`. Для пустого массива цикл сразу пропускается и ответ `0`. На `[1, 3, 3, 7]` при `key = 3` ответ `1`: при равенстве продолжаем искать левее, не останавливаемся на первом найденном совпадении.

### 8. Элемент большинства

Это алгоритм голосования Бойера — Мура. Если большинство было, удаление двух *разных* чисел его сохранит: всего стало на два меньше, а представителей большинства — не более чем на одного меньше. Значит, истинное большинство не исчезнет при таком сокращении. Но у массива без большинства тоже может остаться последний кандидат: например, из `[1, 2, 3]` уберём `1` и `2`, останется `3`, хотя в исходном массиве этого недостаточно.

1. Начать с `balance = 0`. При нулевом балансе взять текущий элемент как кандидата и поставить баланс `1`. При ненулевом балансе совпадение увеличивает его на один, несовпадение уменьшает на один — мысленно вычёркиваем пару. Массив при этом не меняется.
2. Если баланс нулевой, вернуть `0`. Иначе вторым проходом посчитать **в исходном массиве**, сколько раз встречается кандидат. Баланс первого прохода — не число вхождений.
3. Если `count > n / 2`, записать кандидата в `*out` и вернуть `1`; иначе вернуть `0`, не трогая `*out`. Два прохода дают `O(n)` времени и `O(1)` дополнительной памяти. При `n == 0` никакой кандидат не читается.

### 9. Быстрое возведение матрицы в степень

1. Взять `result = I` (единичная матрица), `base = A`, `p = e`. Инвариант: `result * base^p` равно искомой степени по модулю `1009`.
2. Пока `p > 0`: если `p` нечётно, умножить `result` на `base`; разделить `p` на `2` с отбрасыванием остатка; если `p` не ноль, возвести `base` в квадрат. На примере `A^5` собираем `A · A^4`, а не умножаем `A` само на себя пять раз.
3. Каждое произведение вычислять в отдельный выходной буфер. Остаток `% 1009` берём для каждой ячейки результата умножения, прежде чем копировать её обратно. Можно переиспользовать `matmul` с выходом `long long` и один временный буфер под произведение; оба входных аргумента при возведении в квадрат могут быть одним читаемым массивом.
4. Когда `p == 0`, вернуть или скопировать `result`. При `e == 0` он с самого начала равен `I`. При `e >= 2` — `O(log e)` матричных умножений, всего `O(n³ log e)` времени и `O(n²)` дополнительной памяти.
